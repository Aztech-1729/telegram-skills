# Flow review artifact

Use this structure when a concrete audit would help. Fill observed facts; mark
unknowns explicitly. Don't invent conversion results, live checks or client support.

| View / state | User goal | Message / fields | Action + role | Authorized transition | Failure / recovery |
|---|---|---|---|---|---|
| … | … | … | … | … | … |

Record the framework/API/client baseline, private/group/topic context and language.
For each consequential action, record object identity, ownership/permission rule,
duplicate-delivery behavior and what happens when the displayed version is stale.

Review button text without its color or emoji. Check Back/Cancel separately from
destruction, and completion copy against persisted business state. Include empty,
invalid, denied, offline, expired, loading, uncertain and completed states where
they apply. List an actual acceptance scenario for every identified defect.

Conclude with observed defects and proposed corrections, the affected resources,
checks actually performed and remaining live-client checks. Prioritize lost work,
wrong ownership, misleading payment state and inaccessible main actions before
cosmetic refinements.
